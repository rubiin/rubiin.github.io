The `unknown` type in TypeScript is a strict version of `any`. Like `any`, it accepts any value, but TypeScript won't let you use that value without narrowing its type first.

## The problem with any

Let's look at an example to make this clearer:

```js
function readAny(val: any) {
  return val.trim();
}
```

In the above example, we use the `any` type for the value. Since `trim` is a string function, this works fine for string data. However, when you supply numbers or booleans, you get a **runtime error**. `any` skips type checking entirely.

## Why unknown is safer

The same example using `unknown`:

```js
function readAny(val: unknown) {
  return val.trim(); // typescript error at this line
}
```

TypeScript throws a compile-time error here, because we're using a string function without a type assertion. To fix it, the correct code narrows the type first:

```js
function readAny(val: unknown) {
  if (typeof val === 'string')
    return val.trim();
}
```

By checking `typeof val === 'string'`, TypeScript narrows `val` to `string` inside the block, and the error disappears, while staying safe for every other type.

## Conclusion

`unknown` is `any` with guardrails. You can assign anything to it, but you have to narrow it before you call methods on it. Use it when you genuinely don't know the type at compile time, like user input or third-party API responses.
