The `unknown` type in TypeScript is a common type you'll likely come across. It's a strict version of the `any` type: like `any`, it accepts any data type, but there's a minor difference between them. Since an `unknown` value can hold multiple types, TypeScript forces you to perform a type assertion (or a type check) before using any of the type's functions.

## The problem with any

Let's look at an example to make this clearer:

```js
function readAny(val: any) {
  return val.trim();
}
```

In the above example, we use the `any` type for the value. Since `trim` is a string function, this works fine for string data. However, when you supply numbers or booleans, you get a **runtime error** — `any` skips type checking entirely.

## Why unknown is safer

The same example using `unknown`:

```js
function readAny(val: unknown) {
  return val.trim(); // typescript error at this line
}
```

TypeScript throws a compile-time error here, because we're using a string function without a type assertion. To fix it, the correct code narrows the type first:

```js
function readAny(val: unknown) {
  if (typeof val === 'string')
    return val.trim();
}
```

By checking `typeof val === 'string'`, TypeScript narrows `val` to `string` inside the block — and the error disappears, while staying safe for every other type.

## Conclusion

The `unknown` type in TypeScript provides a safe alternative to `any`, offering type safety while still allowing flexibility in dynamic programming. When a value is of type `unknown`, it forces developers to perform type checks before using the value, reducing the risk of runtime errors. This encourages more deliberate and safer code practices compared to `any`, which bypasses type checking. The `unknown` type is particularly useful in scenarios involving user input or third-party APIs, where the exact type may not be known at compile time.
