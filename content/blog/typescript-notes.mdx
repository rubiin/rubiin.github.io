Practical TypeScript notes from everyday work — the unknown type, null and undefined checks, composing types, and the gotchas that trip people up. Each tip comes with before-and-after code examples.

## Type safety essentials

### The unknown type

`unknown` functions like `any`, but does not allow methods to be called on it without narrowing. TypeScript throws a compile-time error if we use a string function without a type assertion. To fix it, the correct code would look like:

```js
function readAny(val: unknown) {
  if (typeof val === 'string')
    return val.trim();
}
```

### Checking for null and undefined

To check for both `null` and `undefined`, use `==`:

```js
if (value == null) // check for both null and undefined
```

### Literal types

Literal types let you create a set of specific allowed values:

```js
type Direction = "North" | "South" | "East" | "West";
```

Literal types also create a type guard for your field, so the compiler can catch errors or typos:

```js
let directionError: Direction = "east" // Type '"east"' is not assignable to type 'Direction'
let direction: Direction = "East" // OK
```

### Type guards with `is`

Type guards are used with the `is` keyword to assert whether a value is of a certain type:

```js
type Rectangle = {
  length: number,
  breadth: number
}

type Square = {
  size: number
}

type Shape = Rectangle | Square;

function isRectangle(shape: Shape): shape is Rectangle {
  return "length" in shape && "breadth" in shape;
}

function isSquare(shape: Shape): shape is Square {
  return "size" in shape;
}

function printArea(shape: Shape) {
  if (isRectangle(shape)) {
    console.log(shape.length * shape.breadth);
  }
  if (isSquare(shape)) {
    console.log(shape.size * shape.size);
  }
}
```

Here we tell TypeScript: if the function returns `true`, the value is of that type. Notice that the guard could also be defined as:

```js
function isSquare(shape: Shape): boolean {
  return "size" in shape;
}
```

However, TypeScript won't know the shape is `Square` even if it returns `true` — so it's best to use the `is` form for type checking.

## Composing types

### Intersection types (`&`)

Intersection types behave like inheritance in classes — the attributes of one type are inherited by another type without duplication:

```js
type Point2d = {
  x: number;
  y: number;
}

type Point3d = Point2d & {
  z: number;
}

const p1: Point2d = {x: 1, y: 2}
const p2: Point3d = {x: 1, y: 2, z: 9}
```

`Point3d` has all the members of `Point2d` plus member `z`. All members in intersection types are required — not passing `z` on a `Point3D` will cause an error.

### Union types (`|`)

A union type is defined with the pipe operator `|`. The value can be either of the single types or a combination — all properties of the combination are optional:

```js
interface A {
  a1: string,
  a2: string,
}

interface B {
  b1: string,
  b2: string;
}

type UnionAB = A | B;

const unionAB1: UnionAB = {
  a1: 'xxx',
  a2: 'xxx',
  b1: 'xxx',
  b2: 'xxx',
};

const unionAB2: UnionAB = {
  a1: 'xxx',
  a2: 'xxx',
};

const unionAB3: UnionAB = {
  b1: 'xxx',
  b2: 'xxx',
};

// Error
// Property 'a1' does not exist on type 'B'.
console.log(unionAB3.a1);

const unionAB4: UnionAB = {
  a1: 'xxx',
  a2: 'xxx',
  b2: 'xxx',
};

// Error
// Property 'b1' does not exist on type 'UnionAB'.
// Property 'b1' does not exist on type 'A'.
console.log(unionAB4.b1);

// Error
// Type '{ a1: string; b2: string; }' is not assignable to type 'UnionAB'.
// Property 'b1' is missing in type '{ a1: string; b2: string; }' but required in type 'B'.
const unionAB5: UnionAB = {
  a1: 'xxx',
  b2: 'xxx',
};
```

### Optional properties (`?`)

Optional variables in a type are annotated with `?`. This means the value may or may not be passed — it works on class variables as well:

```js
type PointXd = {
  x: number;
  y: number;
  z?: number;
}

const p1: PointXd = {x: 1, y: 2}
const p2: PointXd = {x: 1, y: 2, z: 5}

console.log(p1)
console.log(p2)
```

### The keyof operator

`keyof` extracts an object's properties as literal types:

```js
type Person = {
  age: number;
  phone: string;
}

type PersonKeys = keyof Person; // "age" | "phone"
```

You can combine it with the `in` operator to set all fields to a specific type:

```js
type Student = {
  [key in keyof Person]: number;
}

const student: Student = {
  age: 18,
  phone: "1252672"    // Type 'string' is not assignable to type 'number'
}
```

### Index signatures

Objects in JS can be accessed with an index signature — `Obj[key]`, similar to arrays. In TypeScript we can define the type of the index while accessing object values:

```js
type Person = {
  userName: string;
  address: string;
}

const p1: Person = {
  userName: 'alex123',
  address: '123 Main St.',
}
const p2: Person = {
  userName: 'ryan123',
  address: '123 Main St.',
}

type PersonDictionary = {
  [key: string]: Person
}

const persons: PersonDictionary = {
  alex: p1,
  ryan: p2
}

persons['alex'].userName = 'alex567'

console.log(persons['alex'])
```

### Tuples

Tuples are arrays with a fixed length and type per position:

```js
let tuple: [string, number] = ["rubin", 25];
```

### Generic constraints

Generic constraints require generic parameters to have a particular structure. If you don't specify them and try to access the data's properties, TypeScript throws an error because it doesn't know the data's structure:

```js
const addFullName = <T>(obj: T) => {
  return {...obj, fullName: `${obj.firstName} ${obj.lastName}`};
}
```

Here we define a parameter of generic type `T`. If we try to access the properties of the parameter, even if they exist, we get an error like `Property 'lastName' does not exist on type 'T'`. We can fix this by adding generic constraints, which tell TypeScript the generic has those properties — and require the passed value to have `firstName` and `lastName`:

```js
type NamedValues = {firstName: string, lastName: string};

const addFullName = <T extends NamedValues>(obj: T) => {
  return {...obj, fullName: `${obj.firstName} ${obj.lastName}`};
}
```

### The typeof type

The `typeof` key can be used to extract a type from existing data:

```js
const user = {
  name: "Rubin",
  age: 15,
  address: "Kathmandu"
}

type UserType = typeof user  //  {name: string, age: number, address: string}
```

### Lookup types

Lookup types extract a portion from a complex type and create a new type:

```js
type requestType = {
  payload: {
    name: string,
    user: number,
    roles: {
      edit: boolean,
      create: boolean,
      read: boolean
    }
  },
  params: {
    id: number,
    type: string
  }
}

// if we want to use the type of params as a type then

type Params = requestType["params"]  //  {id: number, type: string }
type Roles = requestType["payload"]["roles"] //  {edit: boolean, create: boolean, read: boolean}
```

### Discriminated unions

Discriminated unions use a common literal property (the discriminant) to tell the types apart, so TypeScript can narrow correctly:

```js
type Circle = { kind: "circle"; radius: number };
type Square = { kind: "square"; size: number };

type Shape = Circle | Square;

function area(shape: Shape) {
  if (shape.kind === "circle") {
    return Math.PI * shape.radius ** 2;
  }
  return shape.size * shape.size;
}
```

## Classes and interfaces

### Interface merging

Interface and `type` are somewhat the same, but `type` offers more features — and `extends` can be used with interfaces where `&` is used with types. Interfaces also support **declaration merging**: if two interfaces with the same name exist, their bodies are merged:

```js
interface Person {
  name: string;
}

interface Person {
  age: number
}

const person: Person = {name: 'Max', age: 27}; // merged into a single Person interface

console.log(person);
```

### Implementing a type

When a class implements a type/interface, it should have all the attributes mentioned in the interface/type — it acts as a blueprint:

```js
type Person = {
  age: number;
  phone: string;
}

// Error below: Type 'Student' is missing the following properties from type 'Person': age, phone

class Student implements Person {
  id: string
}
```

### Abstract classes

An abstract class is typically used to define common behaviors for derived classes to extend. Unlike a regular class, an abstract class cannot be instantiated directly — the unimplemented methods are to be implemented by the classes that extend it:

```js
abstract class Logger {
  abstract prefix(): string

  log(message: string) {
    console.log(this.prefix() + ":" + message)
  }
}

class ConsoleLogger extends Logger {
  prefix(): string {
    return "Console"
  }
}

const logger = new ConsoleLogger()
logger.log("Hello")
```

### The never type

The `never` type represents values that can never occur — for example, a function that always throws, or the exhaustive-else branch of a union check. It's the "empty set" of TypeScript types and helps the compiler verify that all cases are handled.

## Everyday gotchas

### Non-null assertion (`!`)

Not-null assertion can be made using the `!` operator — see [this article](https://dev.to/this-is-learning/typescript-tips-tricks-non-null-assertion-operator-21eb) for examples.

### Definite assignment

Definitive assignment (`!`) is used to tell TypeScript that a value will be defined — and it's up to you to make sure it is:

```js
let person: string

function test() {
  person = "rubin"
}

test()

console.log(person)  // error TS2454: Variable 'person' is used before being assigned.
```

Even though `person` is initialized inside the `test` function, TypeScript doesn't know this. To tell TypeScript that this value will always be non-null, add `!` and the error goes away:

```js
let person!: string
```

## Conclusion

TypeScript enhances JavaScript development by introducing static types, which help catch errors early in the development process and improve code maintainability. By providing a type system, it allows developers to define the structure of their code more clearly, enabling better collaboration and understanding in larger codebases.
