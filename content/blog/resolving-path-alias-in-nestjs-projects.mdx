Building a NestJS project in TypeScript is really awesome, but as the project starts to grow, your directories grow too — making your imports lengthy like this:

```javascript
import { User } from "../../user/model";
import { Article } from "../../article/model";

import { Cache } from "../../../../cache";
import { MongoDB } from "../../../../mongodb";
```

## Path mapping to the rescue

TypeScript allows the use of **path mapping**, which lets arbitrary module paths (that don't start with `/` or `.`) be specified and mapped to physical paths in the filesystem via the compiler options in your `tsconfig` file:

```json
{
  "compilerOptions": {
    ...
    "baseUrl": "./src",
    "paths": {
      "@datorama/utils/*": ["app/utils/*"],
      "@datorama/pipes/*": ["app/pipes/*"]
    }
    ...
  }
}
```

The first property we must add is `baseUrl` — notice that paths are resolved relative to `baseUrl`. The second property is `paths`, which tells the compiler: for any module import that matches the pattern `"@datorama/utils/*"`, look in the following location.

## The problem

When you run the code inline (during execution), it works as intended. But when you build it for production and try to run it, you get the following error:

```
Error: Cannot find module '@datorama/utils'
```

The issue is with execution under Node. The problem actually occurs when executing the built files with `node dist/main.js`, not during the build process with `tsc`.

## The solution

After doing some research on the problem, I came across multiple solutions:

- [Using webpack](https://github.com/dividab/tsconfig-paths-webpack-plugin)
- [Using the Module Aliases package](https://medium.com/@caludio/how-to-use-module-path-aliases-in-visual-studio-typescript-and-javascript-e7851df8eeaa)
- Bootstrapping `tsc` with explicit params

Although there are a bunch of solutions above, the first and second didn't work for me. So I went with the third one, which is actually mentioned in the docs of [tsconfig-paths](https://github.com/dividab/tsconfig-paths) — the package Nest uses to resolve these paths at runtime.

To apply the solution, make a file named `tsconfig-paths-bootstrap.js` (the name is up to you) and copy/paste the snippet below:

```javascript
// tsconfig-paths-bootstrap.js

const tsConfig = require("./tsconfig.json");
const tsConfigPaths = require("tsconfig-paths");

const baseUrl = "./dist"; // Either absolute or relative path. If relative it's resolved to current working directory.
tsConfigPaths.register({
  baseUrl,
  paths: tsConfig.compilerOptions.paths,
});
```

Build the dist file normally as you do with `tsc`. After that, you can run it with:

```sh
node -r ./tsconfig-paths-bootstrap.js dist/main.js
```

> Note: Check the file name against the file name in the command and you are good to go.
