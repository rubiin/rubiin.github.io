Environment variables let you keep configuration separate from your code. This makes it easier to deploy the same app to development, test, and production without changing anything in the source.

In this article, I'll share the initial configuration and some tips for using environment variables in NestJS.

## Why use a config module

A common application-level tool is `nestjs-easyconfig`, which loads environment variables from a file named `.env[production|dev|test]`. [Nestjs-easyconfig](https://github.com/rubiin/nestjs-easyconfig) wraps the dotenv module.

## Installation

```bash
$ npm install nestjs-easyconfig
$ yarn add nestjs-easyconfig
```

## Usage

### With a config file supplied (basic):

```javascript
import { Module } from "@nestjs/common";
import { EasyconfigModule } from "nestjs-easyconfig";

@Module({
  imports: [EasyconfigModule.register({ path: "./config/.env" })],
})
export class AppModule {}
```

### With a config file supplied and `safe` set to true:

```javascript
import { Module } from "@nestjs/common";
import { EasyconfigModule } from "nestjs-easyconfig";

@Module({
  imports: [EasyconfigModule.register({ path: "./config/.env", safe: true })],
})
export class AppModule {}
```

By default `safe` is set to `false`. When `safe` is set to `true`, the module compares the supplied env file with the sample env file to find missing keys. If any keys that are in `.env.sample` are missing from the environment in use, it's immediately reported in the console.

> Note: to use this, a sample env file `.env.sample` should be placed in the root directory.

### Without a config file supplied:

```javascript
import { Module } from "@nestjs/common";
import { EasyconfigModule } from "nestjs-easyconfig";

@Module({
  imports: [EasyconfigModule.register({})],
})
export class AppModule {}
```

In this case, you have to pass in the **NODE_ENV** value, and the `.env` file to read will be determined accordingly. It loads environment variables from `.env.[development|test|production][.local]` files. For example, **NODE_ENV=dev** will make the app read `.env.dev`.

> Note: the `.env` file also has to be in the root folder.

## Conclusion

`.env` files keep secrets and environment-specific config out of your code. Load them with `nestjs-easyconfig`, set `safe: true` to catch missing keys early, and your deploy process gets a lot less fiddly.
