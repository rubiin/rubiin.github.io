Last time we learned the basics of the Express web framework — how to set up routes, GET and POST requests, and so on. In this part, we'll talk about **middleware**, which adds more functionality to the Express framework.

Middleware functions are functions that have access to the request object (`req`), the response object (`res`), and the next middleware function in the application's request-response cycle. If you haven't forgotten the last part: `body-parser` and `morgan` are examples of the third-party middleware that Express offers.

## What are middlewares?

Middlewares are a fundamental concept of Node.js, often used in the context of the Express.js framework. In a nutshell, a middleware is a function that has access to the request and response objects of your application. The way I like to think about it: a series of "checks/pre-screens" that a request goes through before it's handled by the application.

For example, a middleware is a good fit to determine if a request is authenticated before it proceeds — returning the login page if it isn't — or to log each request. A lot of third-party middlewares are available that enable a variety of functionality.

### A simple middleware example

```javascript
var app = express();
app.use(function (req, res, next) {
  console.log("Request URL - " + req.url);
  next();
});
```

The code above runs for every request that comes in and logs the request URL. The `next()` method essentially allows the program to continue. If `next()` is not invoked, the program won't proceed further and will halt at the execution of the middleware.

Based on usage, Express classifies middlewares into the following types:

- Application-level middleware
- Router-level middleware
- Error-handling middleware
- Built-in middleware
- Third-party middleware

## Application-level middleware

Think of this as a global middleware — all the routes in your application go through it. This is what we used in the example above: when we call `app.use`, we're saying the entire application instance is going to use this middleware. It doesn't matter which router — whenever a request comes in, it will always run through it. This type of middleware is handy when you want to impose something on every route in your application, like authentication or logging.

**Example:**

```javascript
app.use(function (req, res, next) {
  console.log("Time:", Date.now());
  next();
});
```

## Router-level middleware

Router-level middleware works in the same way as application-level middleware, except it's bound to an instance of `express.Router()`. You load router-level middleware by using the `router.use()` and `router.METHOD()` functions.

**Example:**

```javascript
const express = require("express");

const app = express();

const router = express.Router();

router.use((req, res, next) => {
  console.log("Time:", Date.now());
  next();
});
```

The difference between this and the application-level example is that only the routes defined in this router will use the middleware.

## Error-handling middleware

Error-handling middleware is a little different from regular middleware. Like all the other middleware, it's a function — it just takes one extra argument: the error. It has to be the **first** argument. If you don't put it there, Express won't think you're making an error middleware — it will treat it like regular middleware. If you put error, request, response, and then next, Express knows you're handling errors.

**Example:**

```javascript
app.use(function (err, req, res, next) {
  console.error(err.stack);
  res.status(500).send("Something broke!");
});
```

## Built-in middleware

Starting with version 4.x, Express no longer depends on Connect. The middleware functions that were previously included with Express are now in separate modules. Express has the following built-in middleware functions:

- `express.static` serves static assets such as HTML files, images, and so on.
- `express.json` parses incoming requests with JSON payloads. **Note:** available with Express 4.16.0+.
- `express.urlencoded` parses incoming requests with URL-encoded payloads. **Note:** available with Express 4.16.0+.

## Third-party middleware

In some cases, we'll be adding extra features to our backend — that's where third-party middlewares come into play. Remember `morgan` and `body-parser`? They're examples of these.

**Example:** `body-parser`

All body-parsing middlewares populate the `req.body` property with the parsed body based on the `Content-Type` request header.

```javascript
const express = require('express');
const bodyParser = require('body-parser');
const app = express();

app.use(bodyParser.urlencoded({extended:false}))

app.use(bodyParser.json())

app.post('/save',(req,res)=>{
  res.json({
    "status":true,
    "payload":req.body
  })
})

app.listen(3000,(req,res)=>{
    console.log('server running on port')
})
```

For a partial list of third-party middleware functions commonly used with Express, see the [third-party middleware](https://expressjs.com/en/resources/middleware.html) list.

## Best practices

A couple of things to keep in mind while using middlewares:

- The order of middlewares in your application matters, as each request goes through them sequentially.
- Forgetting to call the `next()` method in a middleware function can halt the processing of your request.
- Any changes you make to the `req` and `res` objects in a middleware function are available to the rest of the application that uses `req` and `res`.

## Conclusion

Middlewares allow developers to modularize their code by handling tasks such as logging, authentication, error handling, and request parsing. By chaining multiple middleware functions together, Express enables flexible and reusable code, making it easier to build robust, maintainable applications with a clean separation of concerns.
