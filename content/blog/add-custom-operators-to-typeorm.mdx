TypeORM is an Object-Relational Mapper that runs on Node.js and in the browser, supporting platforms like Cordova, PhoneGap, Ionic, React Native, NativeScript, Expo, and Electron — all while working with both TypeScript and JavaScript (ES5 through ES8). Its goal is to always support the latest JavaScript features and to help you build any kind of database-driven application, from small apps with a few tables to large-scale enterprise systems spanning multiple databases.

While TypeORM gives you many operators out of the box, it also lets you extend the framework with **custom operators** of your own. In this post, I'll show you how to build one — an `ILike` operator that was missing from TypeORM's repository API.

## What makes TypeORM flexible

Unlike most other JavaScript ORMs, TypeORM supports both the **Active Record** and **Data Mapper** patterns, which means you can write high-quality, loosely coupled, scalable, and maintainable applications in the most productive way. The framework is heavily influenced by other ORMs, such as Hibernate, Doctrine, and Entity Framework — and it inherits their philosophy of letting you extend behavior when the defaults aren't enough.

## The problem: a missing operator

For repository-style queries, TypeORM ships a set of operators like `Like`, `Between`, and `In`. One operator I needed but couldn't find was **`ILike`** — the case-insensitive equivalent of the SQL `Like` operator.

## Creating a custom operator

Building a new operator for the repository pattern is surprisingly straightforward. The trick is to subclass `FindOperator` and override `toSql` so TypeORM knows how to render your operator into SQL:

```ts
import { Connection, FindOperator, FindOperatorType } from "typeorm";

class FindOperatorWithExtras<T> extends FindOperator<T> {
  constructor(
    type: FindOperatorType | "ilike",
    value: FindOperator<T> | T,
    useParameter?: boolean,
    multipleParameters?: boolean,
  ) {
    // @ts-ignore
    super(type, value, useParameter, multipleParameters);
  }

  public toSql(
    connection: Connection,
    aliasPath: string,
    parameters: string[],
  ): string {
    // @ts-ignore
    if (this._type === "ilike") {
      return `${aliasPath} ILIKE ${parameters[0]}`;
    }

    return super.toSql(connection, aliasPath, parameters);
  }
}

/**
 * Find Options Operator.
 * Example: { someField: Like("%some string%") }
 */
export function ILike<T>(
  value: T | FindOperator<T>,
): FindOperatorWithExtras<T> {
  return new FindOperatorWithExtras("ilike", value);
}
```

In the example above, we build an `ILike` operator that TypeORM doesn't provide by default. Because it extends `FindOperator`, it plugs straight into the same query-building pipeline as the built-in operators — so you can use it anywhere a normal operator would work:

```ts
const users = await userRepository.find({
  where: { firstName: ILike("%rubin%") },
});
```

## Wrapping up

Custom operators let you close the gaps in TypeORM's default API with a few lines of code. Subclass `FindOperator`, override `toSql` to emit the SQL you need, and expose a factory function that mirrors the built-in operators — and you have a first-class operator your queries can use just like any other.
