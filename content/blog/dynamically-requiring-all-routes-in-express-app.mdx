If you're using the Express framework to develop a web application, you're probably familiar with routing and the important role it plays. Routing refers to how an application's endpoints (URIs) respond to client requests. You define routes using methods on the Express `app` object that correspond to HTTP methods — for example, `app.get()` handles GET requests and `app.post()` handles POST requests. You can also use `app.all()` to handle all HTTP methods, and `app.use()` to attach middleware as a callback.

As your app grows, registering routes one-by-one in a single file becomes tedious and error-prone. In this post, we'll look at a small trick — dynamic routing — that requires every route file automatically.

## The problem with manual requires

I like to fragment my routes into separate files and require them in the root JavaScript file. This not only improves code readability, it also makes debugging a lot easier, since you can pinpoint the exact location in the exact file instead of digging through a wall of code in one file.

To use your fragmented routes, you have to require them like any Node.js module and pass them to `app.use`. That's simple if your routes folder has a couple of routes — but in a large-scale web app there may be a dozen or more route files. You'd have to require each file individually, and `app.js` quickly becomes cluttered with route-import boilerplate.

There's another downside: with many routes, there's a real chance you'll forget to register one.

## Dynamic route loading

A quick fix is **dynamic routing**, which automatically requires every route in the `routes` folder, reducing boilerplate and making the process easier:

```javascript
const fs = require("fs");

/**
 * Dynamic Routing
 * Adds all routes from the routes folder
 */
fs.readdir("./routes", (err, files) => {
  if (err) throw err;

  files.forEach((file) => {
    app.use("/", require("./routes/" + file));
  });
});
```

Here we use the filesystem module to read every file from the `routes` folder and register it on the Express `app` instance.

## Wrapping up

Dynamic route loading keeps `app.js` clean no matter how many route files you add — you'll never forget to register a route again, and new route files are picked up automatically. For most projects the few lines above are all you need.
