If you do continuous delivery or continuous integration, you'll frequently run into Jenkins. It's a core part of our CI/CD pipeline, and the moment you need to stand up a fresh instance, the plugin setup can become a chore. This post shows how I packaged a Jenkins image with all the plugins pre-installed — so you can skip the setup wizard entirely.

## Why we love Jenkins

- It is an open system that is platform, language, and methodology agnostic, letting us support a diverse client base with one non-proprietary CI/CD platform.
- It is the industry reference implementation for what a CI/CD system should be, with a rich ecosystem of more than 1,100 plugins that integrate Jenkins with everything from Active Directory to GitHub to the OpenShift PaaS.
- It is focused on CI/CD, and is not trying to be what it is not (Git repository, Chat client, Docker storage, etc.).
- You are not locked into any proprietary vendor — it has major industry support and many engineers are already familiar with it.
- It offers a plethora of features out of the box, so you don't have to search Google for hacks.

## The pain: plugin setup

However, one thing that has been a pain over years of using Jenkins is the initial setup — mostly the plugin installation. I mean this:

![](/blog/custom-jenkins-images-with-plugins-pre-installed/jenkins.png)

So I wrote a custom Jenkins image with all the plugins pre-installed, a default user, and Docker plus Docker Compose installed — for people who want to use Jenkins without the hassle of configuring it:

```dockerfile
FROM jenkins/jenkins

ENV JENKINS_USER admin
ENV JENKINS_PASS admin

# Skip initial setup
ENV JAVA_OPTS -Djenkins.install.runSetupWizard=false


COPY plugins.txt /usr/share/jenkins/plugins.txt
RUN /usr/local/bin/install-plugins.sh < /usr/share/jenkins/plugins.txt
USER root
RUN apt-get update \
    && apt-get install -qqy apt-transport-https ca-certificates curl gnupg2 software-properties-common
RUN curl -fsSL https://download.docker.com/linux/debian/gpg | apt-key add -
RUN add-apt-repository \
   "deb [arch=amd64] https://download.docker.com/linux/debian \
   $(lsb_release -cs) \
   stable"
RUN apt-get update  -qq \
    && apt-get install docker-ce -y
RUN usermod -aG docker jenkins
RUN apt-get clean
RUN curl -L "https://github.com/docker/compose/releases/download/1.24.0/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose && chmod +x /usr/local/bin/docker-compose
USER jenkins
```

### A slimmer alpine variant

Worried about image size? I've got you covered — I also wrote an Alpine-based image for people who are space-conservative:

```dockerfile
FROM jenkins/jenkins:alpine

ENV JENKINS_USER admin
ENV JENKINS_PASS admin

# Skip initial setup
ENV JAVA_OPTS -Djenkins.install.runSetupWizard=false


COPY plugins.txt /usr/share/jenkins/plugins.txt
RUN /usr/local/bin/install-plugins.sh < /usr/share/jenkins/plugins.txt
USER root
RUN apk add docker
RUN apk add py-pip
RUN apk add python-dev libffi-dev openssl-dev gcc libc-dev make
RUN pip install docker-compose
USER jenkins
```

For the full source code and the `plugins.txt` file, check out my repo at https://github.com/rubiin/jenkins

> Note: I specifically wrote these images for a project where I was using Docker Compose to manage my container stack, so feel free to omit the Docker and Compose setup if you don't need them.
